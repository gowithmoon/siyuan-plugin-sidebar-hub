# 固定行高虚拟化与可见范围计数

状态：已接受  
日期：2026-09-27  
取代：[ADR-0001](./0001-async-entry-counts.md)

## 背景

页面、数据库和标签的完整结果会随知识库增长。直接挂载全部逻辑可见条目，会让 DOM 数量随结果规模线性增加；面向完整结果集加载页面引用数量和数据库记录总数，也会为用户尚未浏览的条目产生请求。

分页虽然能减少单页 DOM 数量，但会中断侧边栏的连续滚动，并不能解决页面的跨笔记本扫描、完整搜索与排序，也不能自然限定计数请求。思源原生标签面板会递归创建完整标签 DOM；原生文档树则按层级展开加载直接子文档，两者都不符合本插件完整结果搜索、排序和页面排除规则的边界。

## 决策

- 页面和数据库使用项目内的固定行高虚拟平铺列表；标签先按折叠和搜索状态拍平成逻辑可见行，再复用相同的虚拟窗口。
- 行高固定为 31px，窗口上下各保留 8 行缓冲。参数是实现常量，不增加用户设置或数据迁移。
- 条目来源继续生成完整的可搜索、可排序结果，不感知滚动位置、视口尺寸或行高。展示层只把稳定条目 key、滚动位置和视口高度交给虚拟窗口。
- 搜索或排序后回到顶部；刷新、数据失效和标签折叠变化通过首个可见条目 key 与行内偏移恢复附近位置。
- 页面引用数量和数据库记录总数只以当前虚拟窗口及缓冲范围内的稳定 key 为目标。缓存、失败隔离、并发或批量限制以及 generation 写回隔离仍由条目来源负责。
- 普通文档正文保存不驱动页面来源更新。页面更新时间排序和页面引用数量使用最近一次成功加载或手动刷新得到的结果；用户需要最新值时通过页面标签页的刷新操作主动获取。
- 页面完整扫描 generation 保护扫描和计数请求的写回；旧计数请求不能写回新的扫描结果，来源销毁时隔离在途结果。保存事件不创建额外的计时器、计数轮次或请求。
- 页面首次扫描完成后一次构建完整结果；刷新时保留上一次成功结果，完成后原子替换。

## 被拒绝的方案

- **页码分页、游标分页或“加载更多”**：破坏连续导航，且无法消除完整搜索、排序、页面扫描和离屏计数的成本。
- **第三方虚拟化库**：当前只有固定行高、单列窗口和 key 锚点需求，项目内模块足以覆盖，新增运行时依赖不会带来相称收益。
- **复制思源原生标签 DOM 模型**：折叠仅隐藏后代，不能约束已创建的节点数量。
- **复制思源原生文档树取数模型**：按展开加载直接子文档与页面面板的跨笔记本完整搜索、排序及日记祖先排除规则不兼容。

## 结果

- 页面、数据库和标签只挂载视口附近的行，同时保留完整搜索、排序和原有打开目标。
- 离屏页面和数据库不产生计数请求，已完成计数可在滚动返回时复用。
- 固定行高要求相关列表行保持一致高度；新增可变高度内容前必须重新评估本决策。
- 虚拟窗口与标签拍平保持为可独立测试的展示层 seam，条目来源不承担 UI 滚动状态。
